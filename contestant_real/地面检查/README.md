# 地面检查

**不起飞**的地面检查，在跑 `basic_test` 和 `单机测试/` 之前做。
飞机放在起降垫上通电即可，不解锁、不起飞。

| 脚本 | 查什么 | 清单项 | 前提 |
|---|---|---|---|
| `c3_双机链路.sh` | 网络 / 管控 / DDS 互见 / 数据频率 | — | 通电即可；DDS 那两层要飞行栈 |
| `c1_原点标定.sh` | 原点标定的**重复性** | A4 | 飞行栈起着、飞机静止 |
| `c4_执行器.sh` | 执行器：核飞控参数（Set 映射从飞控读）+ 单次动作 | G1 / G3 | 飞行栈起着（执行器不解锁也能动） |
| `c5_夹爪往复.sh` | 夹爪张开/闭合 3 次，间隔 3 秒 | G3 | 同上 |
| `c6_发射器.sh` | 发射机构连发 3 次，间隔 3 秒 | G3 | 同上 |

爪子行程下端=抓紧 / 上端=打开、发射器上端=发射位 / 下端=装填复位。

**发射机构也一起被拦**（破窗弹发不出去），所以改行程后两机都要 `--params` 一遍。

NX01 的发射位/装填位因此是 **2100 / 900**，方向和 NX02 一样（上端发射）。

⚠️ 还没验的只剩 **NX01 的爪子**（`c5` 只在 NX02 上跑过）——侦察机任务里不用爪子。

## 顺序为什么是这个

**`c3` 最先** —— 它分四层（网络 → 管控 → DDS → 数据），坏在哪一层一眼看出来，
而且前两层不需要飞行栈。链路不通的话后面两项根本做不了。

**`c1` 第二** —— `world->odom` 的平移是 `set_origin_from_uwb` 一次性锁死的，
后面**所有跟坐标有关的测试都建立在它之上**。2026-09-24 那次里程计没收敛就锁，
偏差 0.47/0.67 米整场飞行都带着，而且表现成"航点都差一点"而不是"标定错了"。

**`c4`/`c5`/`c6` 最后** —— 它们是唯一会让硬件动起来的几项，放在链路和定位都
确认之后，而且 `c4 --params` 先把飞控参数核一遍再动。

## c1 的判据

连续多次锁定，锁出来的平移量应当基本重合：

| 最大标准差 | 结论 |
|---|---|
| < 0.05 m | ✓ 好 |
| 0.05 ~ 0.15 m | △ 勉强，再等里程计稳一会儿重测 |
| > 0.15 m，或有次数失败 | ✗ 不要飞，先查 UWB / 里程计 |

节点自己的门限是 `max_std_dev_m=0.15`，那是**单次采样窗口内**的离散度；
这里测的是**多次之间**的一致性，是更严的判据。

## c4 为什么先核参数再动执行器

**接错口会驱动别的输出，而且不报错** —— 指令照样被飞控 ACCEPTED（2026-10-14
在 NX01 上就是这样：`PWM_MAIN_FUNC5` 还是出厂的 408，SDK 打印"完成"、机构一动
不动）。所以动执行器之前先 `--params`，它把飞控里的实际值读回来逐项比。

核哪些参数**不写死在脚本里**，是按 SDK `SERVO_CONFIG` 里每一路的 `output`
自动展开的。2026-10-15 改装后应该读到：

```
PWM_MAIN_FUNC7  = 301    MAIN7 = Actuator Set1（爪子之一）
PWM_MAIN_FUNC9  = 301    MAIN9 = Actuator Set1（爪子之二，与 MAIN7 同一个槽位、天生同步）
PWM_MAIN_FUNC5  = 302    MAIN5 = Actuator Set2（发射器）
PWM_MAIN_MIN/MAX 7、9    1000 / 1950     ← 10-18 改（上一版 900/2100），两机相同
PWM_MAIN_MIN/MAX 5       800 / 2200（NX02）/ 900 / 2100（NX01）  ← 🔴 两机不同
PWM_MAIN_TIMx   = 50     舵机那几组频率 50 Hz（电机那组是负值，与执行器无关）
COM_PREARM_MODE = 2      不解锁也允许动执行器
```

**接线和 Set 映射两机相同**（用户 2026-10-15 确认"侦查机为同样设置"），当天两机
飞控都按当时的表配齐、两边 `--params` 实测全绿（NX01 的 `PWM_MAIN_TIM3` 也从 400
改成了 50）。🔴 **但 10-18 起发射机构的行程两机不同**（NX01 900~2100、NX02 800~2200；爪子
两机都是 1000~1950），表按各自飞控写 —— 所以 **`--params` 必须两机分别跑**，
一架绿不代表另一架绿。

改装前用的 `MAIN10` 现在空出来了，`PWM_MAIN_FUNC10` 应当归 0 —— 不归零的话它
还挂在 Set1 上，抓放时会跟着动。`--params` 不查这一条（它只按表里列出的口核），
要自己在 QGC 里确认一眼。

参数没全对就**一下都不动**。确认无误后再 `--open` / `--grip` 单次动作，
或 `c5_夹爪往复.sh` 连续 3 个来回。

⚠️ **张/合方向会随装配翻**：2026-10-09 是 900~2200/2200=抓紧，2026-10-15 改装后是
**900~2100、900=抓紧、2100=打开**。软件只认 `SERVO_CONFIG` 里显式的
`pwm_action`/`pwm_idle`，不按行程端点推——所以每次动过机械结构，都要用
`c5_夹爪往复.sh` 现场看一眼张合对不对，别等到任务里才发现抓放做反了。
**两机一致性只能人判** —— 舵机没有位置反馈，软件读不到角度。

## c3 的四层与常见结论

| 层 | ✗ 的含义 |
|---|---|
| 网络 | AP 问题。5G ch149/80MHz 是已验证的健康配置；txpower 的 3dBm 是 mt7925 假读数，别查它 |
| 管控 | `control_server` 挂了（它是开机自启的，不是容器没起）→ `systemctl restart uav-control-server` |
| DDS | 飞行栈没起，脚本会直接说明并给出起它的 curl；都起着还看不到才是域号/Peer 问题 |
| 数据 | `uwb/pose_abs` 没在发 |

**"两机互见"这一项值得单独说**：编队靠僚机订阅长机位姿。两机各自跟地面站通
**不代表它们之间通** —— AP 下多播不可靠，靠的是 entrypoint 生成的静态 Peers
（`/tmp/docker_sim_cyclonedds.xml`）。Peer 配反的表现是"单飞都正常、一编队就
跟不上"，到现场才发现就晚了。

> 判据里用 `ros2 topic list --no-daemon`。不加 `--no-daemon` 会读 ROS 2 daemon
> 的缓存，**一个 RMW/域配错的 shell 也会返回完整列表**，看着正常。
