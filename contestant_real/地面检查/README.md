# 地面检查

三项**不起飞**的地面检查，在跑 `basic_test` 和 `单机测试/` 之前做。
飞机放在起降垫上通电即可，不解锁、不起飞。

| 脚本 | 查什么 | 清单项 | 前提 |
|---|---|---|---|
| `c1_原点标定.sh` | 原点标定的**重复性** | A4 | 飞行栈起着、飞机静止 |
| `c2_舵机.sh` | 舵机接线/飞控参数 + 两机行程一致性 | G1 / G3 | 飞行栈起着（舵机不解锁也能动） |
| `c3_双机链路.sh` | 网络 / 管控 / DDS 互见 / 数据频率 | — | 通电即可；DDS 那两层要飞行栈 |

```bash
cd ~/ai_uav/docker_sim/contestant_real/地面检查
./c3_双机链路.sh          # 先做这个，它不需要飞行栈也能查到前两层
./c1_原点标定.sh          # 两机各锁 5 次
./c2_舵机.sh --params     # 先只核飞控参数，确认无误再去掉 --params
./c2_舵机.sh
```

## 顺序为什么是这个

**`c3` 最先** —— 它分四层（网络 → 管控 → DDS → 数据），坏在哪一层一眼看出来，
而且前两层不需要飞行栈。链路不通的话后面两项根本做不了。

**`c1` 第二** —— `world->odom` 的平移是 `set_origin_from_uwb` 一次性锁死的，
后面**所有跟坐标有关的测试都建立在它之上**。2026-09-24 那次里程计没收敛就锁，
偏差 0.47/0.67 米整场飞行都带着，而且表现成"航点都差一点"而不是"标定错了"。

**`c2` 最后** —— 它是唯一会让硬件动起来的一项，放在链路和定位都确认之后。

## c1 的判据

连续多次锁定，锁出来的平移量应当基本重合：

| 最大标准差 | 结论 |
|---|---|
| < 0.05 m | ✓ 好 |
| 0.05 ~ 0.15 m | △ 勉强，再等里程计稳一会儿重测 |
| > 0.15 m，或有次数失败 | ✗ 不要飞，先查 UWB / 里程计 |

节点自己的门限是 `max_std_dev_m=0.15`，那是**单次采样窗口内**的离散度；
这里测的是**多次之间**的一致性，是更严的判据。

## c2 为什么先核参数再动舵机

SDK 的 `SERVO_CONFIG` 里 **NX01 那一路从来没在真机上核对过** —— 源码注释原话：
"接线和飞控参数还没在NX01真机上核对过，暂按NX02的第一路照搬"，并且写着
**"接错口会驱动别的输出"**。所以在给 MAIN7 发 PWM 之前必须先确认它真的被配成
舵机输出。脚本核这四项（源码注释点名要确认的）：

```
PWM_MAIN_FUNC7  = 301    MAIN7 = Actuator Set1（SDK 舵机1）
PWM_MAIN_FUNC9  = 302    MAIN9 = Actuator Set2（SDK 舵机2，只 NX02 有）
PWM_MAIN_TIM2   = 50     该组频率 50 Hz（舵机要 50Hz）
COM_PREARM_MODE = 2      不解锁也允许动执行器
```

参数没全对就**不会**往下走行程。`--params` 可以只核参数、一下都不动舵机。

行程走 `800 -> 1400 -> 2000 -> 1400 -> 800`，每档停 1.5 秒（`800`=抓紧 /
`2000`=松开，NX02 2026-09-21 真机已验）。**两机一致性只能人判** —— 舵机没有
位置反馈，软件读不到角度，脚本只负责把两机按同样的节奏驱动，幅度一不一致
要盯着机械机构看。

## c3 的四层与常见结论

| 层 | ✗ 的含义 |
|---|---|
| 网络 | AP 问题。5G ch149/80MHz 是已验证的健康配置；txpower 的 3dBm 是 mt7925 假读数，别查它 |
| 管控 | `control_server` 挂了（它是开机自启的，不是容器没起）→ `systemctl restart uav-control-server` |
| DDS | 飞行栈没起，脚本会直接说明并给出起它的 curl；都起着还看不到才是域号/Peer 问题 |
| 数据 | `uwb/pose_abs` 没在发 |

**"两机互见"这一项值得单独说**：编队靠僚机订阅长机位姿。两机各自跟地面站通
**不代表它们之间通** —— AP 下多播不可靠，靠的是 entrypoint 生成的静态 Peers
（`/tmp/docker_sim_cyclonedds.xml`）。Peer 配反的表现是"单飞都正常、一编队就
跟不上"，到现场才发现就晚了。

> 判据里用 `ros2 topic list --no-daemon`。不加 `--no-daemon` 会读 ROS 2 daemon
> 的缓存，**一个 RMW/域配错的 shell 也会返回完整列表**，看着正常。
