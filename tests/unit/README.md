# SDK 离线单元测试

```bash
python3 tests/unit/test_sdk.py              # 0.1 秒
python3 -m unittest discover tests/unit     # 等价
```

**不需要 ROS、不需要起仿真、不需要网络、不需要装任何东西**（只用标准库
`unittest`，不是 pytest——赛场没网，测试不该要求先装包）。

## 为什么要有

改 SDK 原来的唯一关卡是整轮试飞：**5~16 分钟，而且一轮只能验一条路径**。
但 SDK 里大量逻辑跟飞行无关——航点跳过判据、收件箱语义、解散通知的成败
处理、几何换算、限速恢复——这些 0.1 秒就能验完。

## 怎么做到不装 ROS 也能跑

`capabilities.py` 顶层 import 了 `rclpy` / `rcl_interfaces` / `std_srvs`，
这些只装在 docker 镜像里。`_ros_stub.py` 装了个 import 钩子，遇到这些包就
现造空壳模块；**contest_sdk 自己的模块不碰**，测的是真代码。

被测方法用 `DroneSDK.__new__()` 造实例、不跑 `__init__`（它要连 ROS），
只注入那个方法真正用到的几个属性。`servos` 这类是 property，用一次性子类
覆盖。

## 测了什么

**挑 2026-10-01 真出过事的那些，每条对应一次实际故障**，不为覆盖率凑数：

| 测试类 | 对应的真实故障 |
|---|---|
| 航点跳过判据 | 阈值 0.05 m 比悬停漂移还小，判不出"已在脚下"，飞机对着十几厘米残差算 atan2，白转近 290° |
| 收件箱语义 | 可靠通道"先 ACK 再查处理函数"，没注册的事件被确认后丢弃；多轮流程不复位会读到上一轮旧数据 |
| 解散通知 | `state['sent']` 写在 send 之前，发失败时兜底被自己堵死，僚机干等 600 秒 |
| 间距默认值 | `spacing_m` 只动态挂、类上没声明，编辑器认不出来 |
| 几何 | `step_forward` 返回局部 z 当 AGL 发给队友，两机 odom 原点不同会偏 |
| 发射与抓放 | 连发声光播几次；没配舵机不能抛异常 |
| 直飞限速 | 用完必须恢复 0.3，异常路径也要恢复，否则落点精修带着高限速跑 |

没出过问题、又跟飞行强耦合的部分（规划器交互、编队跟随回路、视觉闭环）
不在这里测——那些留给试飞，单元测试替代不了。

## 验证过它们真能逮住回归

把两个已修的 bug 临时改回去，测试立刻红：

```
ROUTE_SKIP_M 改回 0.05   -> 3 个用例失败
_fire_disband 改回"先置位再发" -> 1 个用例失败，并打出
    AssertionError: True is not false : sent 置位了的话 finally 的补发会被跳过
```

加新测试时也该这么验一遍：**先让它失败，再让它通过**。不然可能写了个
永远为真的断言。
